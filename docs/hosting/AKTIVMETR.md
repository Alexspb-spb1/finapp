# Переезд приложения на app.aktivmetr.ru

## Выбор адреса

Адрес программы и входа: `https://app.aktivmetr.ru/`. Корневой `https://aktivmetr.ru/` предназначен для отдельного сайта о продукте (описание, тарифы, кнопка «Войти» → `https://app.aktivmetr.ru/`); `www.aktivmetr.ru` может вести на этот сайт. Публиковать сборку программы на корневом домене нельзя. Сайт о продукте проектируется и выпускается отдельно, когда согласованы содержание и тарифы. GitHub остаётся хранилищем исходного кода; GitHub Pages по старому адресу `/finapp/` продолжает работать на этапе проверки. Production Firebase project ID и данные не меняются.

## Подготовка без изменения DNS

1. Дождаться принятия брендового PR. Для пробной публикации использовать отдельный Firebase staging project и его адрес `*.web.app` (либо preview channel). Production Hosting и домен пока не затрагивать.
2. Собрать приложение с текущими переменными соответствующего Firebase проекта: `npm ci && npm run build:hosting`. Эта сборка имеет Vite base `/`. Обычный `npm run build` по-прежнему собирает GitHub Pages с base `/finapp/`.
3. Конфигурация `firebase.json` публикует `dist` и направляет маршруты интерфейса, включая `/accept-invite/:id`, на `index.html`. Серверные банковские маршруты здесь пока не настроены: BANK-003 ещё не активирован. Перед включением банка добавить конкретные rewrite-правила **перед** общим правилом SPA, развернуть обработчики и пройти отдельную проверку.
4. На staging проверить вход, восстановление доступа, приглашение по прямой ссылке, обновление вкладки на маршруте приглашения, чтение и запись данных. Запускать проверки только с конфигурацией staging Firebase.

## Подключение production

1. После успешной приёмки создать или выбрать Hosting site для приложения в `finapp-prod-10a83`, опубликовать подготовленную production-сборку и проверить на его `*.web.app` адресе. Deployment должен включать только Hosting; Firestore Rules и Functions этой операцией не заменяются. Для будущего сайта на корневом домене использовать отдельный Hosting site/проект публикации, чтобы деплой программы не затирал сайт о продукте.
2. В Firebase Console → Hosting → Add custom domain для сайта приложения ввести `app.aktivmetr.ru`. Firebase выдаст индивидуальные DNS значения. Сверить DNS-серверы домена: записи меняются у активного DNS-провайдера, даже если домен куплен в REG.RU. Внести только показанные Firebase записи, не изменяя почтовые MX/SPF/DKIM. Дождаться статуса Connected и HTTPS.
3. Добавить `app.aktivmetr.ru` в разрешённые домены Firebase Authentication. Отдельно обновить ссылки приглашений и настройки почтовых действий на новый origin. Корневой домен и `www` подключать в рамках отдельного выпуска сайта о продукте.
4. Перед сменой основного адреса сверить последние записи компаний в Firestore. `companyStore` сначала сохраняет в localStorage и асинхронно пишет в Firestore; localStorage старого домена недоступен новому. При расхождениях сначала восстановить облачную копию, затем переключать пользователей. На новом домене потребуется повторный вход.
5. Проверить в реальном браузере из пользовательской сети вход, компанию, транзакции и приглашение. GitHub Pages оставить доступным на переходный период, особенно для уже отправленных приглашений с токеном во фрагменте URL; их нельзя бездумно перенаправлять.

## Банк

После активации BANK-003 зафиксировать один HTTPS callback на `app.aktivmetr.ru` и точно такое же значение Redirect URI в песочнице Сбера. Банковский обработчик и секреты остаются на серверной стороне. Затем проверить полный sandbox round-trip и только после отдельной приёмки настраивать промышленный сервис. Нельзя считать смену домена проверкой банковской подписи или доступности mTLS.
